A C# REST API that lets you manage video game characters through a RESTful interface, with JWT authentication and role-based access control.
Built with ASP.NET Core, Entity Framework Core, and SQL Server.

## Changelog

See [CHANGELOG.md](./CHANGELOG.md) for a history of changes to this project.

## Project Structure

| File | Description |
|------|-------------|
| `Program.cs` | Configures services, JWT authentication, and the middleware pipeline |
| `Controllers/VideoGameCharacterController.cs` | Handles CRUD routes for characters |
| `Controllers/AuthController.cs` | Handles login, token verification, and user management routes |
| `Models/Character.cs` | Defines the `Character` entity that maps to the database table |
| `Models/User.cs` | Defines the `User` entity that maps to the database table |
| `Models/RolesEnums.cs` | Defines `UserRoles` and `CharacterRoles`, the fixed sets of valid roles for each entity |
| `DTOs/` | Request and response shapes that define what goes in and out of the API |
| `Services/VideoGameCharacterService.cs` | Business logic for character CRUD operations |
| `Services/AuthService.cs` | Business logic for authentication, password hashing, and user management |
| `Services/DbClaimsTransformation.cs` | Re-checks each user's role and active status from the database on every authenticated request |
| `Data/AppDbContext.cs` | Entity Framework Core database context and unique constraints |
| `Migrations/` | Entity Framework Core migration history |
| `Screenshots/` | Screenshots of the API in action and the database |

## Endpoints

### Public
| Method | Route | Description |
|--------|-------|-------------|
| POST | `/api/Auth/login` | Logs in a user and returns a JWT access token |

### Authenticated
| Method | Route | Description |
|--------|-------|-------------|
| GET | `/api/Auth/verify-token` | Confirms the token is valid and returns the current user's info |
| GET | `/api/VideoGameCharacter` | Returns all characters |
| GET | `/api/VideoGameCharacter/{id}` | Returns a character by ID |

### Admin only
| Method | Route | Description |
|--------|-------|-------------|
| POST | `/api/Auth/register` | Creates a new user |
| GET | `/api/Auth/users` | Returns all users |
| GET | `/api/Auth/users/{id}` | Returns a user by ID |
| PUT | `/api/Auth/users/{id}` | Updates an existing user |
| DELETE | `/api/Auth/users/{id}` | Deletes a user |
| POST | `/api/VideoGameCharacter` | Creates a new character |
| PUT | `/api/VideoGameCharacter/{id}` | Updates an existing character |
| DELETE | `/api/VideoGameCharacter/{id}` | Deletes a character |

## Requirements

- .NET 10 SDK
- SQL Server

### NuGet Packages

| Package | Purpose |
|---------|---------|
| `Microsoft.AspNetCore.Authentication.JwtBearer` | JWT authentication middleware |
| `Microsoft.AspNetCore.OpenApi` | Generates the OpenAPI spec for the API |
| `Microsoft.EntityFrameworkCore` | ORM and database toolkit |
| `Microsoft.EntityFrameworkCore.SqlServer` | SQL Server database provider |
| `Microsoft.EntityFrameworkCore.Tools` | EF Core migrations tooling |
| `Scalar.AspNetCore` | Interactive API documentation UI |
| `System.IdentityModel.Tokens.Jwt` | JWT creation and validation |

Password hashing uses `Microsoft.AspNetCore.Identity.PasswordHasher`, which ships with the ASP.NET Core Web SDK. No separate package required.

Restore all dependencies:

```bash
dotnet restore
```

### Running the Project

1. Clone the repository
2. Update the connection string in `appsettings.json` to point to your SQL Server instance:
```json
"ConnectionStrings": {
  "DefaultConnection": "Server=localhost;Database=VideoGameCharactersDb;Trusted_Connection=True;TrustServerCertificate=True"
}
```
3. Generate a secure signing key and replace the `AppSettings:Token` value in `appsettings.json`:
```bash
openssl rand -base64 64
```
```json
"AppSettings": {
  "Token": "your_generated_key_here",
  "Issuer": "VideoGameCharacterApi",
  "Audience": "VideoGameCharacterApiUsers"
}
```
4. Apply the migrations to create the database and tables:
```bash
dotnet ef database update
```
5. Insert the first admin user directly in the database. To generate the hashed password, create a new console project with the following content and run it:
```csharp
using Microsoft.AspNetCore.Identity;

var hasher = new PasswordHasher();
var hash = hasher.HashPassword(null!, "your_password");
Console.WriteLine(hash);
```
Then copy the output and use it in the INSERT statement:
```sql
INSERT INTO Users (FirstName, LastName, Email, PasswordHash, IsActive, Role)
VALUES ('Admin', 'User', 'admin@company.com', 'your_hashed_password', 1, 'Admin');
```
6. Run the application:
```bash
dotnet run
```
7. Open the interactive API docs at:
https://localhost:{port}/scalar/v1

## Notes

- The `Id` is always generated by the database. It is never sent in POST or PUT request bodies.
- `POST /api/Auth/register` and `POST /api/VideoGameCharacter` return `201 Created` on success.
- `DELETE` returns `204 No Content` on success.
- Duplicate emails are not allowed. `Email` must be unique (case insensitive).
- Duplicate characters are not allowed. The combination of `Name` and `Game` must be unique (case insensitive).
- Passwords are hashed with `PasswordHasher` before being stored. Plain text passwords are never saved.
- `role` on a user must be one of: `Admin`, `Normal`.
- `role` on a character must be one of: `Hero`, `Villain`, `Figurant`, `AntiHero`.
- `FirstName` and `LastName` are limited to 50 characters, `Email` to 70 characters, `Password` to 72 characters.
- Users can be deactivated (`IsActive = false`) without being deleted, either through `PUT /api/Auth/users/{id}` or directly in the database. Deactivated users cannot log in.
- All character write routes (`POST`, `PUT`, `DELETE`) and all user management routes require admin privileges. Non-admin users will receive a `403 Forbidden` response.
- Every route in this API requires a valid JWT, including reading characters. There are no public read endpoints besides login.
- An admin cannot delete their own account. Attempting to do so returns a `403 Forbidden` response.
- The first admin user must be set manually in the database. After that, admins can create and manage other users through the API.
- To access protected routes in Scalar, add an `Authorization` header with the value `Bearer {your_token}` to each request, or use the built-in authentication field if available.
- All error responses follow standard HTTP status codes (`401` unauthorized, `403` forbidden, `404` not found, `409` conflict, `500` internal error).
